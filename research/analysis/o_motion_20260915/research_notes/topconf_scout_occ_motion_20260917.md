## 深读一：OccProphet 的实际代码与可证伪含义

论文的 Observer–Forecaster–Refiner 解决的是计算量与时序 feature 预测。官方实现中 `TemporalAttention.create_temporal_attn_mask` 使用下三角 mask（`unet_trans.py:43-58`），`HybridFusion` 将 scene global、BEV window 与 height 三路分别聚合，再各做 temporal attention（`unet_trans.py:124-183`）。`ConditionalGenerator` 先由输入时序的 pooled feature 生成动态 3D convolution kernel，再一次性展开未来时刻 feature（`unet_trans.py:212-289`），这是比逐时刻自回归更便宜的 feature extrapolation。

但它不能作为当前“运动传输到占据”的先行实现。`OccProphet.__init__` 明确分别构造 `occ_predictor` 与 `flow_predictor`（`occprophet.py:77-89`）；`extract_feat` 对同一 ego-aligned voxel feature 分别跑两套 encoder（`:410-433`）；`forward_train` 分别以 `vox_feats`→`pts_bbox_head` 和 `flow_feats`→`flow_head` 计算 loss（`:636-642`）。占据 head 未接收 predicted flow，故不能用其 occupancy gain 证明 flow 让占据地址发生了物理搬运。其 `warp_features` 将 3D flow 归一化、round 成整数格并在目标格 overwrite（`:278-344`），这是离散 ego/feature warp；不保留多源质量，也不是可微的 source-point transport。

与项目的关系是：它提供低成本时序编码的工程基线，但当前 D 的问题已经不是缺少一层 temporal attention。若要借用，唯一合理的最小试验是把已冻结 D residual 改接一个**可微 destination sampler**，比较“flow 只作独立 head”与“flow 改变 occupancy readout 地址”两条件；保持 O 全场通路、CRN-CV 起点、完整 moving/static 分母与相同四个 h。静止 XY EPE 变差或 occupancy 无收益即停止，不能以速度/显存变化替代科学结果。

## 深读二：DynamicCity 的实际代码与可迁移边界

DynamicCity 的 `TrEncoder` 不把时间折叠成普通 frame channel：`down_ratios` 显式列出 xy/xz/yz 与 tx/ty/tz 六平面（`vae/encoder.py:30-40`），还可以用 separate time encoder 与 one-hot time（`:23-27,42-65`）。`process_plane` 把未保留的维度展平为 token，经过独立 Transformer 后还原到对应 plane（`:142-150`）。`hexplane_to_rollout` 再将六张平面拼入单二维张量（`utils/hexplane_utils.py:4-37`），DiT 以固定二维 patch token 加入 trajectory/command/layout 条件（`diffusion/models.py:120-142,213-256`）。

这提供的是一种“时间—空间地址显式分解”的状态表示，不是 motion ground truth，也不是传感器预测器。它的训练数据是 CarlaSC/Waymo 4D occupancy 序列，配置 `sequence_length:16`, `spatial_size:[128,128,8]`；没有当前项目的 camera+radar、CRN box/vel 或虚拟材料点标签。因此不能直接拿它的 4D generation mIoU 代替项目的 moving/static XY EPE 或未来 GMO。低成本可证伪实验应只取 D/O 的冻结特征，在现有四 h 上加一个小型 tx/ty/tz factorized adapter（零初始化、保留 O 与 CRN-CV），检查它是否降低 moving EPE 且不抬高 static EPE；若只是压缩误差或对静态背景过拟合，就不能保留。

## 建议只保留的两个方向

1. **Source–query implicit transport decoder（首选）**：沿 DIO 的表示级耦合，将当前预测对象/材料 source 与未来 destination query 放进同一 readout；flow 不作为孤立输出，而是改变 occupancy query 地址，保留 O 全场兜底与 CRN-CV 强对照。实验顺序固定为 **train512 训练、dev200 仅评价**，阈值和路由规则不能看 dev 后选择；必须超过已完成的 **8 阈值 D-speed 路由** moving-benefit/static-cost 对照。当前 `.5` 阈值在 dev 上保留 **97.89% moving 收益**，但静止额外 EPE 仍为 **+0.02055 m**，应作为必须击败的门槛。只训小 decoder 也必须在 train512 固定规则后一次性评估 dev200，同时看 moving/static XY EPE、全场 occupancy/change 与 coverage 分层；若未超过该路由或静止漂移不降，立即停。
2. **Factorized temporal spatial state（次选）**：借 DynamicCity 的 tx/ty/tz 显式时间—空间因子，但只做小型 residual adapter，不做完整 generative DiT。仍固定 train512 训练、dev200 评价和预注册阈值，必须与 8 阈值 D-speed 路由及 `.5` 阈值的 97.89% moving / +0.02055 m static 对照比较；目标是检验 D 当前四个 h 是否缺少可迁移的时空地址状态，而不是继续堆 attention/loss/gate。

本轮没有下载模型权重、运行论文模型、连接远端训练，也没有改动 state/automation/源代码。

## 根 agent 代码与概念复核补充

OccProphet 构造器还支持 `shared_predictor`，不能把独立 predictor 描述为所有配置的必选结构。决定性事实是核到的训练路径分别用特征计算 occupancy/flow 输出，没有把预测 flow 作为 occupancy transport 的输入。DIO 的 flow 改变 query 出现在一致性训练；其 occupancy 可直接查询未来时空坐标，不能声称推理必然沿 flow 递推。`source-query` 是表示启发，不是因果使用已被证明。dev200 已多轮参与研究判断，只作为开发评价，最终泛化另需未参与选择的场景。
