# 密集历史确实改善 DELTA，但仍未超过 CV+D：结束外部三维速度扩展

2026-09-17。16 个 train 锚点、8 个 scene；相同历史起止时刻，96 条六相机序列从 2 帧增加为 5–7 帧。冻结官方 DELTA/Metric3D，不训练外部模型，不修改 O/M0。推理和独立几何/评分复算均完成。

## 结果与研究判断

**历史中间帧有用，但没有改变当前强对照胜出的结论。** 2 s XY 位移 EPE（m，对象等权、越低越好）如下。表中图像方法均在原 CRN 覆盖区域保留 CV，仅在覆盖外查询图像运动场；缺少支持的点使用既定零运动回退。

| 方法 | moving，137 个对象 | stationary，184 个对象 |
|---|---:|---:|
| CRN-CV | 3.022346 | 0.092182 |
| CV+D，固定 0.5 m/s 规则 | 2.737708 | 0.101027 |
| 匹配两帧 RAFT + FB | 3.294486 | 0.390325 |
| 两帧 DELTA + 官方 vis | 2.997021 | 0.266921 |
| 密集 DELTA，端点差分 + 端点 vis | 2.898934 | 0.188692 |
| 密集 DELTA，当前锚定 LSQ + 全帧 vis | 2.893744 | 0.188366 |

增加历史帧后，端点差分相对两帧对照同时改善 moving 与 stationary，不能把先前失败简单归为“历史图像没有运动信息”。但密集 LSQ 相对已有 CV+D 仍差 0.156036 m / 0.087340 m，四个 horizon（0.5、1、1.5、2 s）均在两个组上落后。它也未完成任何 O 占据评价，因此没有“超过 O”的结果。

LSQ 相对密集端点估计仅有约 0.005190 m 的 2 s moving 差异、0.000326 m 的 stationary 差异，且质量/有效掩码不同，不能解释为已证明多帧拟合机制有效。没有把毫米级开发集差异包装成新方法。

不做 vis 筛选时，混合两帧 DELTA 为 3.019913 / 0.399132 m，密集端点为 2.899357 / 0.268212 m，密集 LSQ 为 2.898092 / 0.265391 m。因此密集输入相对两帧的改善也出现在不加质量筛选的完整估计器比较中；不能唯一归因于 vis 筛选变化。它仍可能同时涉及轨迹变化、几何支持变化和时间深度一致性，不是单一机制因果证明。

单独图像场、不使用原 CRN-CV 时，密集 LSQ + quality 的 moving / stationary EPE 为 5.926256 / 0.457903 m；这进一步限制把该图像速度场当作主预测器的合理性。

## 完整人口、输入和支持率

原 41,122 个材料点、四个 horizon 的有效对象数 373/366/358/359 与有效点数 40622/39975/38639/39460 均保留。没有丢掉低置信度、缺少表面支持或远处对象。材料点由 GT 当前框定义，评分查询固定输入侧三维场；它们不是认证可见表面，也不是 O 的原生物理运动输出。

全部原材料点的支持数：

| 场 | 未加质量筛选 | 加官方 vis |
|---|---:|---:|
| 两帧 DELTA | 11508 | 9533 |
| 密集端点 | 10936 | 9611 |
| 密集 LSQ | 10935 | 9491 |

2 s moving 对象等权 quality 支持比例分别为密集端点 30.33%、LSQ 29.47%；stationary 为 27.69%、27.35%。这与按所有材料点计数的分母不同。LSQ 要求所有帧有效/可见，端点估计只要求端点，两者支持掩码必须分别报告。

输入认证覆盖 654 张不同 JPEG：5 帧序列 3 条、6 帧 12 条、7 帧 81 条。所有相机帧的 sample_data prev/next 链连续、时间严格递增，首尾 sample_data、K、pose、image 与原两帧输入逐项一致；每帧文件 hash 和真实姿态已核验。相邻帧实际间隔 0.049767–0.2 s。输入截止仍是原同步包 input_availability，可能稍晚于 t0 LiDAR；不声称严格 LiDAR 时间戳零延迟预测。

固定当前 stride32/phase4 的 1400 点网格。96 条序列的当前 query、Metric3D query depth 和当前参考点与两帧输出逐元素完全一致。新增真实历史帧改变了可用观测量，所以这是信息量诊断；将来若使用这些帧训练主模型，必须增加同输入的 O 对照。

## 实现、核验与运行证据

- 官方 DELTA commit `3367cda1c74d19e73296165f9826b213211678dd` 与官方权重保持不变，64 个源文件与私有依赖通过 hash 校验。没有修改官方模型或共享环境。
- `[oldest,...,current]` 输入，所有 query 在最后一帧，官方 backward tracking、window_len16、默认 36 个 support query 和内部复制填充保持一致。每帧轨迹用实际 K/pose lift 至共同 t0 LiDAR 坐标。
- 端点速度取真实时间差；LSQ 是固定当前三维点、用全部真实时间戳拟合的无权恒速估计。没有速度阈值搜索、标签拟合或 GT 邻居归属。
- 推理源码 SHA256 `cbe86a2734d73f84cab43a4af6fde971ae8fc911f146a461eee864aef640fccc`。评分规则在推理前固定；GitHub `c25bfdb` 在读取本次评分结果前归档协议与核查脚本。
- 正式推理 345.988 s，峰值显存 3.576 GiB，96 条全部完成，零优化更新、没有读 GT。durable runner 与 child 均正常退出并确认进程消失。
- 独立使用 K 线性求解、齐次变换、`numpy.linalg.lstsq` 重算原始三维轨迹、速度、t0 点和 masks。三维点差低于 5.7e-13 m，保存 float32 速度/点的误差低于 7.7e-6，相应 masks 逐元素一致。
- 两个方案各独立复算 46,592 个 XY/XYZ 误差标量，合计 93,184 个，最大差 7.11e-14 m。全部原评价人口检查一致。

这验证了接入、几何和算术，不是独立验证集泛化、统计显著性或理论误差界。当前只有 train16/8 scenes 的开发证据。

## 决策与下一步

依据运行前判据，**停止继续扩展“外部深度/跟踪器 → 确定三维速度 → 固定 CV 外推/覆盖外替换”路线**。保留这些冻结输出作为以后分析的参考，不再靠继续换 tracker、增加门控或挑阈值延长当前路线。也不把失败解释为视觉本身没有价值；预训练深度尺度、表面到体积的归属、外推假设和任务连接仍是不同可能原因。

O/M0 与 CV+D 保留，S3 不恢复。下一阶段将计算预算投入一个能够被未来占据读出直接使用的状态原型，并与同输入、相近参数和充分匹配训练量的直接 future-latent 预测/简单增容对照竞争。要回答的是合法历史观测如何改变未来任务输出，不是再追加一项与终端占据脱节的辅助运动损失。

后续通过标准仍需原协议 future GMO、moving recall、静止 FP 等终端指标；物理误差只在接口认证后报告。单 seed11，先开发选定，再使用未被反复选方案的场景确认。当前目标“超过 O 且运动更准”继续进行中。
