# 对象状态中的时间交互：实际结构诊断与下一候选

2026-09-16。v1 条件模块尚未进入原生训练。以下证据改变候选设计，不是性能比较，也不把未训练的 v1 判为实验负例。

## 发现与成立范围

v1 用当前预测对象编码产生 32 个 scene latents，随后给每个 latent 加同一 `time_mlp(h)`，再送入原生查询的 cross-attention。对固定对象状态、查询、有效集合和权重，普通多头注意力的每个头有

`K_j(h)=K_j(0)+W_K t(h)`，`V_j(h)=V_j(0)+W_V t(h)`。

同一查询对所有 key 的分数被加上同一常数，softmax 权重保持不变；所有 value 的公共平移只在输出中保留一个公共项。因此这一直接路径可写成

`delta(states, query, h) = A(states, query) + B(h)`。

实际代码 dropout=0，没有额外 bias token / zero-attention token，也没有在加时间后再做对象相关的非线性。这些条件使上述分解适用于 v1 的最后一层 query attention 及线性输出投影。原生递推查询、action 条件和后续 transformer 仍可产生间接交互；不能把这项结论扩大为“整个系统不能学习运动”。

## 实际数值检查

在 H200 现有 Torch 2.1.2 环境的 **CPU** 上，使用实际 v1 模块的 query-attention 参数、两个不同 latent 集合和同一 query，计算两个时域的输出差，并和闭式公共 value 平移比较。仅为 float64 代数检查，没有 CUDA、optimizer、数据集预测或模型效果测量。

- 时间变化的输出最大幅度：0.16491477959452733。
- 两个不同 latent 集合之间的时间差响应偏差：5.551115123125783e-16。
- 与闭式 value 平移的最大偏差：3.885780586188048e-16。
- 检查的 v1 源码 SHA：`cdaf1ef70a2ca11ee7d027817046d767b5b341727694f07d24d9f9bee244102c`。

实际回执：`receipts/conditioner_time_bias_actual_cpu_v1.json`。另经独立源码推导复核。微小浮点差异不是对象与时间交互能力的证据。

## 决策：让已有运动证据形成明确的时域相关输入

CRN 的来源修正后，当前预测框和速度的恒速外推已在原完整稀疏支持上优于 D：2 秒 moving XY EPE 为 3.386739 对 4.208240 m。这给出了比“期待小数据训练自行学会时间与速度相乘”更直接的输入构造依据。

候选 v2 保留当前 27 维状态接口，在每个名义未来时域附加三个假设中心坐标：

`p_h = p_0 + h * v_eff`，其中 V 用当前预测速度，G 先将速度置零。

全部位置与速度均在当前 LiDAR 坐标 R 下；时间固定为原 0.5、1、1.5、2 秒，不读取未来标注时间。归一化后新增坐标为 `packed_center + h*(20/51.2)*packed_velocity`。保留当前中心，避免把参考状态丢掉。状态 MLP 输入从 27 增至 30；V/G 容量相同，总参数从 95,680 变为 95,872。

不按框裁剪稠密输出，不新增分数筛选，不删除越界预测或未检测覆盖的 GT，不把 CRN-CV 位移直接接到最终物理输出。两项任务仍共享经过原生 future-head 的状态链。原时间分支可保留为时域偏置，但不称其本身为对象动力学。

v2 仍是恒速假设；不引入未观测角速度、加速度，也不宣称该构造新颖。其待检验问题是：在固定几何、检测器和容量下，明确的运动外推条件能否同时改善原 O 占据和 D/CRN-CV 物理对照，并产生可信 V−G 增量。先完成真实 CPU 接口检查和原生四更新预检，再冻结正式训练。目标尚未达成。
