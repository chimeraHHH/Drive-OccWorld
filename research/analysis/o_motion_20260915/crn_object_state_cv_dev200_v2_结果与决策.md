# CRN 对象运动状态：修正原点后的结果与推进决策

2026-09-16。**修正来源明确的框原点约定后，现成传感器模型给出的对象速度，在保留全部原评价支持的条件下，四个预测时域均优于当前 D 运动头。** 这将下一动作从盲目增加辅助损失，推进到检验“把预测对象状态直接输入未来场景更新”。它尚未证明占据预测超过 O。

## 先修复跨框架坐标约定

在实际 L40S 官方推理环境中确认：CRN 用 nuScenes 几何中心训练 height；继承的 CenterHead.get_bboxes 扣除半高，返回底面中心的 LiDARInstance3DBoxes；eval_step 直接导出其 tensor，后续 exporter 又将前三项当作几何中心。因此原始 results_nusc 的位置字段在这条运行链中实为底面中心。六个实际导入源文件与本地源码 SHA 一致；没有构造模型、启用 CUDA 或重新推理。

唯一修正为 c = raw_translation + R_export[:,2]·height/2，使用完整旋转（含 ego pitch/roll）。它来自源码，不利用 GT 拟合偏移、不扩大框、不调分数阈值；此前浮点舍入不可逐 bit 逆转。原官方文件、原主指标和 v1 原始导出诊断均保留。v1 的 5.24 m 不代表正确中心约定下的状态预测能力，也不把这次坐标修复当作新算法。

独立几何分解显示：原 2 秒运动材料点仅 41.76% 落在 XYZ 框内，但 83.28% 满足局部 XY；原未覆盖点中 71.30% 是 XY 满足而 Z 被排除。修正后真实 XYZ 覆盖为 **76.19%**，仍保留全部框外点作为零位移预测，不删除漏检对象。

200 anchors / 100 场景、四时域共 16074 对象-时域对。对象内先平均材料点误差，再对 anchor-instance 等权。以下 XY EPE 越小越好。

2 秒运动 XY EPE 降低约 **19.52%**，XYZ 同样由 4.228382 降到 3.409315 m。全部对象的 2 秒 XY EPE 从 1.514652 降到 1.191356 m。静止组低于 D、但仍高于零位移；低速过渡组改善不稳定，2 秒略差。因此不是每组普遍更准，完整 JSON 披露全部组、分位数和区间。

CRN-CV 用的是当前预测框/速度与名义未来时域，不使用未来位姿、GT 速度或实例匹配。与 D 比较仍包含额外检测模型、不同预训练和更长历史；不能归因为某个融合机制。材料点真值是框刚体代理，不是直接实测 scene flow，且不惩罚 GT 支持之外全部假框。

## 已选下一项实验

保留 O、D 和本次 CRN-CV。新的 V/G 成对实验将把对象状态输入原 future-head 的状态更新，保留 O 的稠密预测通路和原完整 GT：V 使用预测速度，G 保留完全相同框几何、类别、置信度和参数容量，仅把速度槽置零。占据解码与物理位移读出共用受条件影响的未来状态；不把框内覆盖设为占据输出硬门。

这一结构受到 MotionPerceiver 对象状态到占据的前向链启发，但其 WOMD 给定状态、二维场景与过滤未见对象未来标签的配方不移植。本项目需要证明真实检测误差下、完整 3D 任务中的速度增量，一般的对象 token/attention 组合本身不构成新颖性。

当前已开始准备原 train512 的官方权重推理资产和新条件模块；尚未启动 V/G 正式训练。新检测预测只推理、不重训练检测器。固定单 seed11，真实训练预检后明确预算；原 S3 不恢复。候选须同时检查原 GMO、运动召回、FP/FN、t0 代价和同支持位移；不仅与 D，还应披露相对现成 CRN-CV 的水平。成功候选再做原 full5119/150 场景验证。
