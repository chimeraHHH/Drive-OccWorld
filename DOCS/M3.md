# RadarFlowOcc M3

Research prototype: per-return Doppler information updates a camera-conditioned
velocity prior; the same posterior mean/covariance drives future BEV transport
and held-out radial prediction. No full M3 training or accuracy result exists.

The branch is isolated from the running M1. Its baseline includes the previously
validated future-metadata-only input and occupancy target-downsampling changes.
M3 uses current single-sweep, causal radar observations, a separate NPZ cache,
and scientific per-sample/per-horizon metrics with sampler-padding removal.

## Files

- `projects/configs/radarflowocc/action_condition_GMO_radar_m3.py`: algorithm config.
- `projects/mmdet3d_plugin/datasets/radar_observations.py`: nine-column returns.
- `projects/mmdet3d_plugin/bevformer/detectors/doppler_posterior_transport.py`: motion state, NLL and forward splat.

- `DOCS/m3_20260906/`: Chinese method/experiment plan, paper outline, literature audit and verification snapshot.

## Prepare a reviewed run

`tools/m3_prepare_config.py` writes a resolved config and does not launch jobs.
Supply existing absolute data/occupancy roots, a new work directory, and an
explicit common initialization (`scratch` or checkpoint). It fixes the common
720 training augmentation, batch=1/GPU, 24 epochs and LR=1e-4 by default.
Use identical choices across baselines. The inherited frozen backbone/BN
settings must also be considered when choosing scratch versus pretrained runs.

`tools/m3_build_observation_cache.py` creates only the new observation cache;
review capacity first. `--limit` is a smoke build, not a complete cache. A cache
path passed to the config helper is read-only during training. Missing/mismatched
records fail rather than silently falling back to the old clipped raster.

`tools/m3_summarize_metrics.py --input RESULTS.pkl --output SUMMARY.json`
reports scene-bootstrap intervals. Add `--compare BASELINE.pkl` for paired
input-minus-baseline differences. Both files must contain matching sample IDs.

## Ablations

- `model.doppler_posterior.transport_mode`: `sigma` (default), `mean`, `off`.
- `model.doppler_posterior.use_doppler_update`: false for camera prior only.
- `model.doppler_posterior.covariance_mode`: `full`, trace-matched `isotropic`,
  or 90-degree `rotated` (only changes transport, preserving the NLL posterior).

## Verification and boundaries

89 CPU tests passed on the existing PyTorch 1.10.1 / NumPy 1.19.5 environment.
Full detector construction and real nuScenes radar plus random BEV module
forward/backward passed at 200x200. The core motion module has 164,355 parameters.
No full camera CUDA forward, DDP trial, GPU timing or scientific accuracy is
claimed. For optional CPU detector construction, the legacy renderer requires
an explicit compiler-compatible CUDA architecture and compiler; use an isolated
TORCH_EXTENSIONS_DIR, as the CPU smoke tool does.

The Gaussian update and sigma-point rule are established tools. Claims should
concern tested observability/forecasting behavior, not invention of Bayesian
inference. Given future GT ego transforms/actions, LiDAR-derived GMO labels,
projected compensated nuScenes radial velocity, local shared constant velocity,
correlated returns and uncalibrated uncertainty all limit interpretation.
